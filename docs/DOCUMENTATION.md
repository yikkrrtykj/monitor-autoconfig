# 文档管理与上下文持久化

维护日期：2026-09-06。目标是任何新会话只靠仓库即可恢复正确的工作状态，聊天不作为唯一事实来源。

## 唯一职责与更新时机

| 信息 | 唯一主要落点 | 何时更新 |
|---|---|---|
| Agent 强制流程 | 根 `AGENTS.md` | 协作协议改变 |
| 用户使用、安装与操作 | 根 `README.md` | 用户可见行为或入口改变 |
| 当前工作和下一步 | `docs/STATUS.md` | 每轮交付、阻断、验收反馈 |
| 稳定领域模型、冻结与安全约束 | `docs/PROJECT_CONTEXT.md` | 明确批准的约束变更或新增事实 |
| 代码/测试、Git、文档制度 | 对应工程规范 | 工作制度或工具链确实改变 |
| 范围、决策、实现、证据 | `docs/iterations/<批次>.md` | 开始、关键决策、提交前、验收后 |
| 可复制的部署/恢复/验收命令 | `docs/runbooks/` | 对应操作或目标版本改变 |
| 跨模块长期设计决策 | `docs/decisions/NNNN-<主题>.md`，需要时创建 | API/架构/持久化/兼容策略有长期取舍 |

不复制多份长状态。STATUS 保持简短，目标约 100 行内；超出则把证据移入迭代记录并链接。
已验收迭代保留，不反复重写历史。发现旧信息不准确时追加更正、日期和来源。
简单修复的决策直接写迭代记录，只有跨模块长期取舍才另建决策文档。

## 内容与证据标准

- 中文正文，文件名使用稳定英文路径；Markdown 标题逐级、代码块标注语言、仓库内相对链接。不依赖聊天附件绝对路径恢复信息。
- 活跃记录包含维护日期、目标、范围、不做事项、状态、基线/实现 SHA、关键决策及理由、验证命令/环境/结果、未测项、生产状态、下一步。
- 状态显式区分 `进行中`、`本地验证完成`、`已提交`、`已推送`、`待生产验收`、`已收口`、`阻断`。无部署的纯文档迭代可在验证并发布后收口。
- 每个结论注明来源：本轮执行、Git 检查、CI 链接、用户验收反馈或历史交接。历史“通过”不改写成当前已复测。
- 保存必要摘要和安全诊断，不入库完整聊天、原始运行日志、真实密码/token/SNMP community、个人信息或事故原文。生产凭据继续留在受保护配置中。
- 操作命令写明执行目录、前置条件、目标版本、失败停止规则和预期结果。不能把会重启/写入/发送通知的动作写成只读检查。
- 规范与代码冲突时先核实。未来计划不得写成现有能力；环境缺失不得写成测试通过；推送不得写成生产部署。

## 迭代收尾顺序

1. 核实实际 diff 和验证结果，填写 [迭代模板](iterations/TEMPLATE.md)。
2. 将用户可见行为/操作变化写入对应说明；长期决策入上下文或决策记录；STATUS 更新为真实状态和唯一下一步。
3. 检查链接、日期、SHA、命令路径、敏感内容和 Git diff；文档随代码提交并 push，核验远端。
4. 准备最小交接摘要：当前目标、已完成、未完成、约束、证据入口、下一条动作。需要部署时同时交付完整命令和网页验收。
5. 持久化成功后执行宿主提供的上下文压缩。压缩工具不存在或失败时，报告实际情况；已保存文档仍作为恢复入口，不能假装已压缩。
6. 新会话/压缩恢复后先读 `AGENTS.md`、STATUS、PROJECT_CONTEXT 和活跃记录，再检查实际 Git 状态；不自动创建新任务或删除聊天代替压缩。

官方说明确认根 `AGENTS.md` 是项目指令入口，相关限制见 [AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。
支持该命令的客户端可用 `/compact`；这属于客户端操作，不能当成 shell 命令，也不能仅通过编辑文件触发，见 [官方命令说明](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。本次配置不修改用户全局配置。
