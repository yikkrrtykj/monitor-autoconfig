## 行为与关键决策

1. `resolve_unifi_identity` 是共享只读解析入口，顺序为显式 `unifi_mac`、Controller 精确地址、持久 inventory 的 `ip/librenms_ip`、Controller 与 inventory 合并后的唯一名称。结果分为 resolved / unresolved / not-an-AP。型号只用于展示。
2. AP 只使用 `unifi-ap:<12位小写MAC>`。已知 AP 但 MAC 缺失或匹配歧义时返回空通知身份，下一轮重试；普通 SNMP 设备保留既有逻辑及空 ledger 启动基线语义。
3. AP watcher、LibreNMS watcher 以及共享发送包装入口使用同一个 `OnlineIdentityService.send_once`。共享入口同时覆盖既有 Ping 首次上线和重新纳管通知；仅 AP 不再强制创建新的部署通知生命周期，普通设备仍保留原重新纳管行为。没有改 Pending/Delete 状态转换或调用破坏性函数。
4. 不能把现时 IP/name 无条件当作历史通知的归属证明。inventory 增加兼容字段 `legacy_online_aliases`：旧记录缺字段时从其原 `ip/librenms_ip/name` 冻结别名；本版新增记录显式保存空列表。旧别名随原 MAC 保留，不因 DHCP/改名更新。仅 inventory 能证明属于目标 MAC、且 Controller/inventory 没有其他归属时复用 `migrate_device_online_identity` 补记 canonical ledger，不发卡。
5. 上述字段由现有 inventory 读写入口维护，不清空或删除 ledger，也不删除旧 IP/name。旧版本会忽略附加字段；如回退运行，旧版再次写 inventory 可能移除该字段，重新升级前必须重新核对迁移证据。迁移写盘失败时暂缓通知，避免把已通知 AP 再发一次。
6. AP outage 按 MAC 保存；无 MAC 的旧状态在唯一解析后合并到 canonical state，保留已有告警、最早掉线时间及 seen-up 信息，不留下两份状态。对同名不同 MAC 不做名称强制合并。旧 provisional outage 暂时存在身份歧义时保留，不能仅因其旧 key 不在 Controller 中就当作设备退役而丢弃。
7. 修正 canonical key 缺少独立 mac 字段时的解析；合法冒号、连字符、点分及裸 MAC 统一，非法 MAC 不作为身份。

## 运维与验收边界

- [本次部署、验收与回滚手册](../runbooks/a-02.1-unifi-mac-hotfix.md) 包含 main 快进、Bridge 重建、configured、三层四开关、源码/容器/HTTP 一致性及网页检查。
- inventory 是 Controller 不可用时的历史证据；如果 Controller 与 inventory 都没有任何 AP 关联信息，按普通设备处理。若地址已被复用但所有可用证据都未更新，系统无法凭空识别新 MAC；不得把历史映射解释为实时物理检测。
- 本修复复用现有投递/持久化服务，不新增跨进程或“消息已投递但 ledger 写盘失败/进程崩溃”的 exactly-once 承诺。
- 新增不同 MAC 的 AP 仍应各发一次新设备卡；同 MAC 的属性变化不创建新部署生命周期。不得以禁用通知作为验收方式。
