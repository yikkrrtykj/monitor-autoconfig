# A-02.1 部署、验收与回滚

维护日期：2026-09-28。由用户在公司服务器执行，Agent 不连接服务器。先完成 committed code audit 并确认目标 SHA 的 CI 通过。

## 前置条件与停止规则

- 把 `<完整目标SHA>` 替换为交付回复中的提交。main 只允许快进，已跟踪文件和暂存区必须干净。
- 保留既有 untracked VERSION、配置备份、日志和运行目录。任何冲突、检查失败、SHA 不符或四开关不符立即停止，不自动修配置或清理文件。
- 本次会重建 Bridge，正常告警可能短暂中断。其他服务不需要重启。不清空任何 state/ledger，不为测试主动发飞书、不执行设备 DELETE。

## 一次性服务器命令

```bash
bash <<'HOTFIX'
set -euo pipefail
cd /root/monitor-autoconfig
target_commit='<完整目标SHA>'
test "$(git branch --show-current)" = main
test "$(git remote get-url origin)" = https://github.com/yikkrrtykj/monitor-autoconfig.git
git diff --quiet
git diff --cached --quiet
git status --short
before_commit=$(git rev-parse HEAD)
git fetch origin main
git cat-file -e "${target_commit}^{commit}"
git merge-base --is-ancestor "$target_commit" origin/main
git merge-base --is-ancestor HEAD "$target_commit"
git merge --ff-only "$target_commit"
test "$(git rev-parse HEAD)" = "$target_commit"
printf 'Before=%s\nTarget=%s\n' "$before_commit" "$target_commit"
cd librenms+grafana

check_delete=$(cat <<'PY'
import json, os, re, shlex, sys
from pathlib import Path
expected = {
    "DEVICE_PENDING_DELETE_ENABLED": "true",
    "DEVICE_AUTO_DELETE_ENABLED": "true",
    "DEVICE_AUTO_DELETE_DRY_RUN": "true",
    "DEVICE_AUTO_DELETE_DRY_RUN_NOTIFY": "false",
}
mode = sys.argv[1]
if mode == "env":
    values = {}
    for line in Path(".env").read_text(encoding="utf-8-sig").splitlines():
        m = re.match(r"^\s*(?:export\s+)?([A-Za-z_][A-Za-z0-9_]*)\s*=(.*)$", line)
        if m and m[1] in expected:
            assert m[1] not in values, "duplicate safety key"
            words = shlex.split(m[2], comments=True)
            values[m[1]] = words[0] if len(words) == 1 else None
elif mode == "compose":
    values = json.load(sys.stdin)["services"]["alertmanager-feishu-bridge"]["environment"]
elif mode == "runtime":
    values = os.environ
else:
    raise SystemExit("invalid check mode")
for key, expected_value in expected.items():
    assert values.get(key) == expected_value, mode + " mismatch: " + key
    print(mode, key + "=" + expected_value)
PY
)
python3 -c "$check_delete" env
docker compose config --quiet
docker compose config --format json | python3 -c "$check_delete" compose

# 仅重建本次变更的 Bridge；bind-mounted 源码需要新进程加载。
docker compose up -d --no-deps --force-recreate alertmanager-feishu-bridge
./deploy-check.sh configured </dev/null
docker compose exec -T alertmanager-feishu-bridge python -c "$check_delete" runtime
source_sha=$(sha256sum alertmanager-feishu-bridge.py | awk '{print $1}')
container_sha=$(docker compose exec -T alertmanager-feishu-bridge sha256sum /app/bridge.py | awk '{print $1}')
test "$source_sha" = "$container_sha"
printf 'Bridge SHA OK %s\n' "$source_sha"
docker compose exec -T alertmanager-feishu-bridge python -c 'import json, urllib.request; d=json.load(urllib.request.urlopen("http://127.0.0.1:5005/health", timeout=10)); assert d.get("ready") is True; print("Bridge HTTP ready=true")'

# 网页没有改动，仍核对已有资源的源码/容器/HTTP 一致性。
file='index.html'
source_sha=$(sha256sum "bigscreen/$file" | awk '{print $1}')
container_sha=$(docker compose exec -T bigscreen sha256sum "/usr/share/nginx/html/$file" | awk '{print $1}')
port=$(docker compose port bigscreen 80 | head -n 1)
port=${port##*:}
[[ "$port" =~ ^[0-9]+$ ]]
http_sha=$(curl --fail --silent --show-error --max-time 20 "http://127.0.0.1:${port}/${file}?verify=${target_commit}" | sha256sum | awk '{print $1}')
test "$source_sha" = "$container_sha"
test "$source_sha" = "$http_sha"
printf 'Web source/container/HTTP SHA OK %s\n' "$source_sha"

# 只输出计数，不输出生产设备、MAC、地址或完整配置。
docker compose exec -T alertmanager-feishu-bridge python - <<'PY'
import json, os
from pathlib import Path
root = Path(os.environ.get("FEISHU_BRIDGE_STATE_DIR", "/bridge-state"))
ledger = json.loads(Path(os.environ.get("DEVICE_ONLINE_STATE_FILE", str(root / "notified-devices.json"))).read_text())
inventory = json.loads(Path(os.environ.get("UNIFI_AP_INVENTORY_FILE", str(root / "unifi-ap-inventory.json"))).read_text())
items = ledger if isinstance(ledger, list) else ledger["items"]
assert isinstance(items, list) and isinstance(inventory, dict)
print("ledger_total=", len(items))
print("canonical_ap_total=", sum(str(v).startswith("unifi-ap:") for v in items))
print("inventory_total=", len(inventory))
PY
cd /root/monitor-autoconfig
test "$(git rev-parse HEAD)" = "$target_commit"
git diff --quiet
git diff --cached --quiet
git status --short
printf '服务器检查完成；仍需网页及自然通知观察验收。\n'
HOTFIX
```

Bridge 刚启动时 watcher 尚在初始化；如果 configured/ready 未通过，停止后等待正常初始化再重跑对应只读检查，不反复重建服务。ledger 计数不是验收的固定值，不能期待强制等于交接时的 84；代码只在对应设备被观察到时迁移，不做人工批量发卡或清库。

## 网页与自然运行验收

1. 从首页进入大屏/控制台，确认设备列表、AP 名称/IP、既有告警展示正常；不要求触发改配置、Apply 或删除操作。
2. 观察既有 AP 在 Bridge 重启和正常轮询后没有集中重复“新设备部署”。如现场自然发生 DHCP/改名，核对同 MAC 没有新部署卡；不要为本次验收主动中断生产 AP。
3. 自然发生的新 MAC 应有一次部署通知；同名不同 MAC 各自独立。同 MAC 的真实掉线/恢复应是一份告警生命周期。没有发生的场景标“未发生/未验证”，不能仅凭无卡判通过。
4. 本地已模拟 Controller 故障、并发和重启，生产不要求人为停止 Controller 或发测试飞书。
5. 回传目标 SHA、configured 摘要、三层四开关、Bridge/Web SHA 和 ready、仅计数与网页/自然观察结果；不贴完整配置、真实凭据、MAC 清单或原始事故内容。

## 回滚方案（仅出现已确认回归时）

不 reset、不 force push、不 checkout 旧文件覆盖生产，不回滚 ledger/inventory，不删除容器 volume。优先追加修复；确需撤销时先在 GitHub Issue #13 记录回归证据，从已同步的 main 新建 `codex/` 修复分支，以普通 revert 保留历史：

```powershell
git status --short
git diff --exit-code
git diff --cached --exit-code
git fetch origin main
git pull --ff-only origin main
git switch -c codex/a021-revert
git revert <本次Hotfix完整SHA>
```

每条命令失败即停止。revert 冲突时人工审查，不强行覆盖。复验 Bridge 相关套件、compileall 和 diff，普通推送修复分支并创建关联 #13 的 PR；记录回滚原因、CI 和生产待验收状态，审查通过后由获授权的人员合并。把上面的部署目标换成合并后的 main 完整 SHA，重新执行相同服务器检查；无需更改四开关。

旧版会恢复原来的重复通知风险，并可能在下次 inventory 写入时去掉附加别名字段，因此恢复 Hotfix 前重新审查迁移证据。回滚不是清空历史通知的理由。
