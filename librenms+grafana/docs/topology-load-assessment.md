# 拓扑采集负荷边界

拓扑页面每 10 秒只读取已经生成的 `edges.json` 和 Prometheus 延迟数据，不会因为打开页面或点击节点而登录交换机，也不会触发 FDB、ARP 或接口全表轮询。

后台拓扑采集默认每 600 秒执行一次，并遵守以下边界：

1. LLDP/CDP、接口名和接口状态只由后台采集器读取，默认单线程、每次 SNMP 请求后间隔 500 ms。
2. ARP 表默认只在 `CORE_SWITCH_PING` 和 `FIREWALL_PING` 对应的三层设备读取。只有这两个配置都为空时才回退到全部拓扑设备；也可用 `TOPOLOGY_ARP_DEVICES` 显式指定。
3. 服务器位置不遍历完整 FDB 表，只按服务器 ARP 得到的 MAC 做精确 OID 查询。
4. 已确认的服务器接入口会持久化。下一轮先验证上次所属交换机；验证成功就不再向全部交换机扇出查询，只有服务器移动或证据消失时才全网重定位。
5. 缺失的链路和服务器位置使用有时限的缓存，页面刷新不会把临时 SNMP 丢包误画成设备移动。

如果未来增加“接口详情”，应沿用相同原则：点击后才查询单个设备，服务端按 `设备 + 接口` 缓存 30～60 秒，设置并发锁和每设备速率限制；不要把详情采集加入页面 10 秒刷新循环。
